1. 获取运行配置

GET /index/dylib_verify/config?dylib_key=...

用于发现最新 API Endpoint、运行配置及签名后的服务端配置。客户端可缓存 Last-Known-Good；Bootstrap 不可用时再使用已有 endpointURL 兜底。

2. 在线验证

POST {$runtimeConfig.verify_path|htmlentities}

支持 application/x-www-form-urlencoded 或 application/json。

3. 签名

hex_lowercase(HMAC-SHA256(canonical, verify_secret))

Protocol v1 canonical
udid\nbundle_id\ndylib_key\ndylib_version\ndylib_build\ndylib_sha256\ntimestamp\nnonce
Protocol v2 canonical
udid\nbundle_id\ndylib_key\ndylib_version\ndylib_build\ndylib_sha256\ntimestamp\nnonce\nprotocol_version\napp_executable\napp_macho_uuid\napp_version\napp_build

字段之间是真实换行符。不要把 JSON 字典排序后直接签名，也不要自行改变 canonical 顺序。

字段类型必填协议说明
udidstring是v1+客户端自己取得的设备标识；验证中心不负责采集。
bundle_idstring是v1+当前 App Bundle Identifier。
dylib_keystring是v1+当前选择的 Dylib Key：...
dylib_versionstring是v1+必须与后台登记版本一致。
dylib_buildstring否v1+填写后按 version + build 精确匹配。
dylib_sha256string按配置v1+后台登记 SHA256 时必须匹配。
timestampint是v1+Unix 秒级时间戳。
noncestring是v1+16~128 字符随机串，每次请求使用新值。
signaturestring是v1+64 位小写 hex HMAC-SHA256。
protocol_versionintv2v2当前 v2 使用 2。
app_executablestringv2v2当前主程序可执行文件名。
app_macho_uuidstringv2v2当前主程序 Mach-O UUID。
app_versionstring否v2用于 app_update 判断。
app_buildstring否v2用于 app_update 判断。
客户端逻辑判断使用 ok + code。 message 是服务器可展示文字，可以原样显示，但不要靠 message 文本判断业务状态。
字段类型说明
okbool验证是否通过。
codestring稳定业务结果码，客户端应按它处理对应状态。
actionstringallow / disable_feature / show_message / block。
offline_grace_secondsint允许离线使用缓存验证结果的秒数。
tokenstring验证通过时的短期签名会话 token。
messagestring服务器返回的可展示消息；客户端可直接显示。
server_timeint服务端 Unix 时间。
access_levelstring服务端解析后的授权等级。
permissionsobject最终权限集合；客户端只消费结果，不自行推导授权类型。
app_identityobject服务端解析出的 App 身份。
app_updateobjectApp 更新数据；是否弹窗由客户端决定。
noticeobject/null远程通知数据；验证中心不负责客户端弹窗。

以下是当前服务端实际使用的字符串结果码。客户端可对需要特殊行为的 code 做分支；未识别的新 code 应按 action 处理，并可直接显示 message。

code含义客户端建议
ok / ok_testing / ok_deprecated验证通过消费 permissions/token/notice/app_update。
bad_request必填字段缺失检查请求字段；message 可直接显示。
method_not_allowed请求方式错误verify 必须 POST。
timestamp_invalid请求时间过期校准时间后重新生成签名。
nonce_invalidNonce 无效重新生成 16~128 字符随机 nonce。
signature_invalid签名格式无效检查是否为 64 位小写 hex。
signature_mismatchHMAC 不一致检查 canonical 顺序、字段值和 Verify Secret。
replay_detected检测到重放生成新 nonce/timestamp 后重新签名。
dylib_unknownDylib 不存在或已停用按 action 停止受保护能力并显示 message。
dylib_key_unconfigured / dylib_key_unavailable服务端 Verify Secret 配置异常服务端问题，不要无限重试。
blacklisted设备被封禁按 action 处理并显示 message。
app_identity_incompletev2 App 身份字段不完整补齐 executable / Mach-O UUID 后重新签名。
app_identity_unknown / app_identity_unbound / app_identity_ambiguous / app_identity_inactiveApp 身份解析失败检查身份字段或后台解析/绑定数据。
app_identity_required当前授权要求 v2 App 身份使用 Protocol v2。
app_not_authorized / license_invalid授权不适用或无效/过期显示 message；实际授权 UI 由客户端负责。
version_unknownDylib 版本未登记检查 version/build 与后台登记是否一致。
version_blocked / version_revoked版本被阻止/撤销按 action 处理并显示版本 notice/message。
integrity_mismatchDylib SHA256 不一致停止受保护能力并检查实际加载文件。
server_error验证服务异常按 action + offline_grace_seconds 处理临时故障。
config_unavailable运行配置暂不可用使用 Last-Known-Good / endpointURL 兜底。
推荐接入顺序
  1. 客户端工程自行取得 UDID、BundleID、版本等业务输入。
  2. 准备请求字段，生成 timestamp + 每次唯一 nonce。
  3. 按 v1/v2 canonical 固定顺序拼接，使用当前 Dylib Verify Secret 做 HMAC-SHA256。
  4. POST 到 verify API。
  5. 先看 ok，再看 code 和 action；message 可直接用于提示。
  6. 验证成功后，客户端自行决定菜单、弹窗、悬浮窗、公告显示等产品行为。

生成代码：概览里的“API 接入示例”会生成测试用 OC 文件，同时生成 API_REFERENCE.md、ERROR_CODES.md、EXAMPLES.md。实际项目可以不用生成 OC，直接按 API 文档自行实现。

服务器与运行配置 低频设置；正常情况下配置一次即可

配置版本：v{$runtimeConfig.config_version}，每次保存自动递增并重新签名。
