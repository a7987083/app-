2. 接入说明 按顺序完成即可

当前选择：请选择已注册 Dylib

A. 客户端接入
  1. 把 clients/ios/ZONDylibVerify/ZONVerifyClient.h/.m 加入 Dylib 工程。
  2. 填写 dylibKey、dylibVersion、dylibBuild、验证密钥和现有 UDID Provider。
  3. 配置至少 2 个独立 bootstrapURLs；保留 endpointURL 作为旧/最后兜底地址。
  4. 调用 verifyWithCompletion:，按 permissions 显示普通/额外菜单；按 app_update、notice 渲染服务器下发提示。
ZONVerifyConfiguration *cfg = [ZONVerifyConfiguration new];
cfg.bootstrapURLs = @[
  [NSURL URLWithString:@"https://bootstrap-a.example.com/index/dylib_verify/config"],
  [NSURL URLWithString:@"https://bootstrap-b.example.net/index/dylib_verify/config"]
];
cfg.endpointURL = [NSURL URLWithString:@"https://api.example.com/index/dylib_verify/verify"];
cfg.dylibKey = @"zonoe.main";
cfg.dylibVersion = @"1.0.0";
cfg.dylibBuild = @"1";
cfg.verifySecret = @"...";
cfg.udidProvider = ^NSString *{ return ExistingProjectUDID(); };
服务器迁移：业务 API 域名不要当作唯一长期锚点。Dylib 会依次尝试多个 Bootstrap、已验签的 Last-Known-Good 配置、多个 API 地址、旧 endpointURL，最后才使用离线授权缓存。
B. API

运行配置：GET /index/dylib_verify/config?dylib_key=...

在线验证：POST /index/dylib_verify/verify，Content-Type: application/json

v2 客户端自动上报：bundle_id、app_executable、app_macho_uuid、app_version、app_build。其中 BundleID 只是证据之一，不能单独获得指定 App 权限。

C. HMAC-SHA256 原文

v1 旧客户端保持不变：

udid\nbundle_id\ndylib_key\ndylib_version\ndylib_build\ndylib_sha256\ntimestamp\nnonce

v2 在完整 v1 原文后追加：

protocol_version\napp_executable\napp_macho_uuid\napp_version\napp_build
D. 响应重点

兼容旧字段：ok、code、action、token、offline_grace_seconds。

2406 新字段：access_level、permissions、app_identity、app_update、notice。

客户端不需要自己判断卡密类型；直接读取 permissions.normal_menu、permissions.extra_menu、permissions.extra_features。SDK 不替换旧的 Index::dylib() / Index::apiface()。

同一 UDID 有多张有效卡时取当前 App 下最高适用权限：global_plus > app_plus > basic > block。 指定 App 身份由服务器根据已解析 IPA 的 BundleID + Executable + Mach-O UUID + active IPA→App 绑定识别；客户端不能通过声明 app_id 获权。 云存档等独立购买权益不从这些等级自动继承。
