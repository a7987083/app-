# Rollback Baseline — 2026091809

## Decision

The project development baseline is reset to `source-v2026091809` / commit `21307ba5ec9b65ce0b5f0643555ccc7f7bec0ad9`.

All releases, release branches, development branches, tags and generated release artifacts created after `2026091809` are considered retired and must not be used as a development or deployment baseline.

## Why later versions are being removed

Versions after `2026091809` introduced Phase 20 and the IPA Management Center workstream, including IPA metadata persistence, scan tasks, parser/worker services, binding, governance, write-back and related runtime/deployment changes.

Production has been intentionally rolled back to `2026091809`. Continuing development on the Phase 20 line would keep architectural coupling and experimental operational components that are no longer part of the selected production baseline. The project will therefore restart refactoring from the last pre-Phase-20 stable release rather than trying to remove Phase 20 incrementally from later releases.

This cleanup is intentional and is not a claim that every later commit was individually defective. The purpose is to restore one unambiguous baseline before the codebase is refactored.

## Retention policy

- Keep `source-v2026091809` as the stable rollback baseline.
- Keep all history/releases at or before `2026091809` unless separately reviewed.
- Remove GitHub releases/tags/branches whose product version is later than `2026091809`.
- Do not reuse Phase 20 database migrations or IPA Center runtime services in the refactor unless they are explicitly redesigned and reintroduced.
- New development must branch from this cleaned `2026091809` baseline.

## Database note

The source rollback does not automatically imply database schema rollback. Phase 20 IPA-specific tables and `ipa_center*` permission rows are outside the `2026091809` baseline and must be cleaned separately after backup/verification.
