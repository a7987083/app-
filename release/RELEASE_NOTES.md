# ZONOE 软件源 2026091702

## 更新内容

- 修复 `2026091701` 只给卡密激活入口增加签名字段、但实际设备验证接口 `Index::apiface()` 仍只返回 `{"msg":"ok"}` 的问题。
- `apiface` 验证成功现在统一返回 `code`、`msg`、`expire`、`ts`、`nonce`、`sign`；其中成功状态为 `code=1`、`msg=ok`。
- `apiface` 使用后台现有 `unlock_sign_key` 生成 HMAC-SHA256；签名原文继续固定为 `udid|expire|ts|nonce`，KEY 不返回、不写日志。
- `apiface` 只选择当前已激活且未过期的授权记录，并以有效授权中的最新到期时间作为 `expire`。
- 修复“仅验证卡”已经绑定同一 UDID 且仍在有效期内时，再次提交被错误提示“解锁码已使用”的问题。
- 仅验证卡对同一 UDID 的重复提交改为幂等验证：直接返回当前有效期和签名字段，不重复激活、不重复增加时长、不重复写授权事件日志。
- 已使用卡提交到不同 UDID、已过期卡、全软件源卡和指定 App 卡的原有已使用判断保持不变。
- 在线更新清单新增 `application/index/controller/Index.php`，确保设备验证接口代码实际进入更新 ZIP。
- 扩展 Phase17 协议契约测试，覆盖 `apiface` 签名字段、有效授权筛选、仅验证卡幂等行为及在线更新清单。

## apiface 成功响应示例

```json
{
  "code": 1,
  "msg": "ok",
  "expire": 1791212773,
  "ts": 1789579293,
  "nonce": "7e8f3b42a1c49d20",
  "sign": "64位HMAC-SHA256十六进制签名"
}
```

## 卡密激活响应

- 首次激活仍保持 `code=0` 兼容行为，并返回 `expire`、`ts`、`nonce`、`sign`。
- 仅验证卡同 UDID 重复提交同样保持 `code=0`，但不会再次延长有效期。

## 数据库

- 本修复版不新增数据库结构。
- 继续使用 `2026091701` 已创建的 `fa_config.unlock_sign_key` 配置项。
- 在线更新中既有幂等迁移可安全重复执行，不会覆盖管理员已经设置的 KEY。

## 兼容性

- 目标环境继续兼容宝塔 PHP 7.0 与 MySQL 5.7。
- 不改变卡密字符串格式、日/周/月/季/年时长定义、`card_scope`、`fa_kami_app`、权限链叠加与换绑规则。
- 保留 GitHub 在线更新的 HTTPS、SHA256、数据库/程序备份、文件覆盖校验和失败回滚机制。
