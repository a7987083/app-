# ZONOE 软件源 2026091701

## 更新内容

- 解锁码激活成功响应新增 `expire`、`ts`、`nonce`、`sign` 四个字段；原有 `code`、`msg`、三种卡密用途、时长计算、权限链叠加、换绑和日志逻辑保持不变。
- `sign` 使用 HMAC-SHA256，签名原文固定为 `udid|expire|ts|nonce`；`nonce` 使用 8 字节安全随机数并以十六进制返回。
- 系统配置新增 `unlock_sign_key`（后台显示“解锁签名KEY”）。管理员在后台填写什么值，服务端就使用什么值作为 HMAC KEY。
- 实际 KEY 不写入 GitHub 源码、不返回到解锁接口、不写入授权事件日志。
- 为避免升级后因 KEY 尚未填写而中断解锁，`unlock_sign_key` 为空时，服务端会在首次解锁前自动生成 32 字节随机 KEY 并写回服务器配置；管理员之后仍可在后台直接替换。
- 全软件源卡、仅验证卡、指定 App 卡均统一返回同一组签名字段，同时继续使用各自原有成功提示文本。
- 本版本包含数据库在线迁移 `2026091701_unlock_signing.sql`，仅新增配置项且不会覆盖已经存在的 KEY；脚本可重复执行。
- 新增协议契约测试和 MySQL 5.7 幂等迁移测试，验证 HMAC-SHA256、字段格式、配置读取、迁移不写死 KEY、重复执行不覆盖 KEY。

## 成功响应示例

```json
{
  "code": 0,
  "msg": "ok，解锁成功",
  "expire": 1791212773,
  "ts": 1789579293,
  "nonce": "7e8f3b42a1c49d20",
  "sign": "64位HMAC-SHA256十六进制签名"
}
```

## 数据库迁移

- `fa_config` 新增配置项 `unlock_sign_key`，分组为 `basic`、类型为 `string`。
- GitHub 中迁移文件只保存空值，不包含任何生产 KEY。
- 如果配置项已经存在，在线迁移不会修改其现有值。

## 兼容性

- 目标环境继续兼容宝塔 PHP 7.0 与 MySQL 5.7。
- 原有成功状态码仍为 `code=0`，不改成其他软件源的 `code=1`。
- 不改变现有卡密字符串格式、卡密时长定义、`card_scope` 权限模型、`fa_kami_app` 映射及授权叠加规则。
- GitHub 在线更新继续使用 HTTPS、SHA256、更新前数据库/程序备份、文件覆盖校验和失败回滚机制。
