# ZONOE 软件源 2026091704

## 更新内容

- 新增“续费入口”应用类型。后台新增/编辑应用时可将应用标记为续费入口。
- 续费入口复用客户端现有“解锁 → 输入卡密”流程，不新增客户端页面或协议；客户端仍自动携带当前设备 UDID。
- 续费入口无论游客、全软件源授权还是指定 App 授权，均强制保持 `lock=1` 且 `downloadURL` 为空，因此只能作为输入卡密续期入口，不能被解锁成可下载应用。
- 输入未使用卡密后继续调用现有激活链：卡密一次性消费，并按 `card_scope` 分别叠加全软件源、仅验证或相同 App 集合的指定 App 授权时间。
- 修复“换绑记录”页面原“清空”按钮实际只重置搜索、没有删除记录的问题。
- 修复“授权事件”页面原“清空”按钮实际只重置搜索、没有删除记录的问题。
- 两个日志页面现分别提供“重置搜索”和红色“清空全部”按钮；清空使用 POST、二次确认、返回实际删除条数，并在成功后刷新页面。
- 清空换绑记录只删除 `fa_card_transfer_log` 日志，不修改卡密、当前授权有效期或剩余换绑次数。
- 清空授权事件只删除 `fa_authorization_event` 日志，不修改卡密或当前授权有效期。

## 数据库

- `fa_category` 新增 `renewal_entry`：`0=普通应用`，`1=续费入口`。
- 新迁移 `release/sql/2026091704_renewal_entry.sql` 兼容 MySQL 5.7，并可重复执行。
- 现有应用升级后默认 `renewal_entry=0`，不会改变原有应用行为。

## 续费入口使用方式

1. 后台新增或编辑一个应用，将“续费入口”设为“续费入口（始终锁定，仅用于输入卡密叠加时间）”。
2. 客户端会继续把该条目显示为锁定状态。
3. 客户点击现有“解锁”，输入未使用卡密。
4. 服务端使用当前客户端携带的 UDID 消费卡密，并按卡密用途叠加对应授权链的有效期。
5. 该续费入口本身不会返回安装包地址，也不会因全软件源卡或指定 App 卡变为可下载状态。
