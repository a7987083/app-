更新内容：
1. 将 a7987083/ipaxiazaizhan- 已验证的 IPA metadata 解析模型迁移到 app-，不再延续 2426 仅依赖 systemd timer 才能解析的方向。
2. 扫描结束后由应用内 IpaWorkerLauncher 检测 discovered 资产并后台 spawn `php think ipa:parse-worker --scheduled`；Parser 仍运行于独立 CLI PHP 进程，不占用 PHP-FPM shutdown worker。
3. systemd parser service/timer 保留为可选运维入口，不再是 Parser 启动的唯一依赖。
4. 扫描阶段读取并持久化 OpenList MD5 内容指纹，兼容 hash_info.md5、hashinfo 与 md5 字段；复用现有 ipa_asset.etag，无需新增数据库列。
5. Parser 发起 Range 前优先查找相同 MD5 已解析资产；命中后直接复用 metadata，避免重复读取远端 IPA。
6. OpenList `/api/fs/list` 新增 30 分钟持久化目录缓存；增量扫描可复用缓存，全量扫描必须强制 refresh 并绕过缓存。
7. HTTP Range 使用固定 256 KiB block cache，单 IPA 网络读取预算限制为 16 MiB。
8. Parser 只读取 Payload/*.app/Info.plist，提取 Bundle ID、应用名、版本、Build、MinimumOSVersion 与 executable；不恢复 Mach-O/dylib/framework/hash 重型解析。
9. `ipa:parse-worker --scheduled` 改为有界批次，新增 `--limit`，范围 1-20，默认单轮最多 20 个 IPA，不再无限 drain 队列。
10. parse_failed 使用 30 分钟 cooldown，失败资产不会高频重试，也不会阻塞后续 discovered IPA；孤立 parsing 状态继续支持超时回收。
11. Parse Worker 不自动调用 IpaCompareService；软件源手工比对/写回继续保留为独立业务能力。
12. 保留 IPA 扫描、资产记录、搜索、删除、清空解析结果、OpenList 数据源、增量/全量扫描、现有后台 UI 以及其它软件源/卡密/Dylib 功能。
13. 清空解析结果仍只清除解析派生数据，不删除 IPA 扫描/发现记录。
